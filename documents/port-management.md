# 端口管理 v1 实施草稿

日期：2026-09-08。代码基线：`c3d96474fbe2f9bbdc984df4354c7199928baf7c`。

本分支实现菜单、配置事务、订阅同步、批量月流量额度/到期日及单入口上传/下载整形。它是供代码审查和隔离主机验收的草稿，尚未完成方案 T01–T31 的真实核心、网络和客户端验收。**尤其是限速分类对非首个 IP 分片存在覆盖缺口，当前不能当作可严格保证的端口带宽上限。**

## 使用入口

中文 `install.sh` 与英文 `shell/install_en.sh` 的菜单 12 均进入同一个 Python 模块。原账户、UUID、密码、Reality 密钥、订阅 Salt 和下载文件名不由本模块重新生成。

需要 Python 3.9+、`python3-yaml`、SQLite 标准库、时区数据、`flock`、`ss` 和正常的 systemd 核心服务。目标机器还需满足相应核心配置检查命令和防火墙探测条件；额度功能需要 nftables、同步时钟及后台服务；限速需要 iproute2、HTB/flower/IFB 能力。先在专用测试机安装依赖，不要在未核验前直接替换生产脚本。

从代码检出目录可以先只读查看：

```bash
PYTHONPATH="$PWD/shell" python3 -m port_manager --json list
PYTHONPATH="$PWD/shell" python3 -m port_manager --json check 10001
```

`--root` 可指向隔离的安装目录样本。它只改变配置/账本路径，**不是系统命令的沙箱**；写入操作仍会调用真实 systemd、nft 和 tc。仓库测试通过注入模拟执行器避免主机变更。

| 菜单 | 功能 |
|---|---|
| 1 | 入口总览，分别显示配置、监听和策略状态；公网可达性单独标记未验证 |
| 2 | 单入口改端口，预览后确认；同端口不重启、不重发 |
| 3 | 检查 TCP/UDP、配置占用和实际监听 |
| 4 | 变更历史与最近一次端口变更的反向回退 |
| 5 | 受支持的 Xray 附加入口查看、添加、删除 |
| 6 | 多选入口，统一或逐项设置月额度、到期日 |
| 7 | 用量、自然月周期和已归档周期 |
| 8 | 批量调整额度/日期、暂停或恢复 |
| 9 | 只选一个入口，设置上传和下载 Mbps；显示限速实现的已知边界 |

选择可用 `#1,#3`、完整 `port_id`、`port:10001` 或 `10001-10010`。范围只筛选已有入口，不创建端口。数字对应多个对象、重复选择或不存在的对象会拒绝提交。

额度默认 GB（十亿字节），显式 `GiB` 为 2³⁰ 字节。空白保留；`unlimited` 取消额度；`0` 立即阻断。日期按显式管理时区计算，默认 `Asia/Shanghai`；`2026-12-31` 包括该日全天，次日零点截止；`never` 表示永不到期。策略调整保留已用量，人工暂停独立于到期和超额。已纳管入口不允许随意变更时区，以免重新分配月周期。

限速为客户端上传/下载两个方向，单位 Mbps（百万比特/秒）。空白保留，`unlimited` 解除该方向，0 拒绝。每个方向使用同一 HTB 类聚合同入口的匹配流量。128 包叶队列、每方向至少 16 KiB 或约 10 ms 流量的突发预算，不代表毫秒级恒定速率。

后台服务通过菜单或以下显式命令安装，安装前会预览其影响：

```bash
PYTHONPATH=/etc/v2ray-agent/port-manager-lib/current python3 -m port_manager install-service
```

它安装 `v2ray-agent-port-policy.service` 和核心启动依赖，先恢复策略再启动核心。交互输入与等待服务启动时不持共享写锁。后台每 10 秒核对计数、周期及规则；nft 内核规则另有时间截止和 30 秒有效期，后台失效后已存在的规则会阻断受控入口。规则被外部整体删除时，删除到故障发现之间仍有窗口，不能承诺零漏计。

## 当前适配边界

下表表示代码中存在适配器，并不表示这些系统组合已通过真实主机验收。

| 场景 | 草稿行为 |
|---|---|
| Xray Reality 独立入口及脚本生成的 45987 内部配对结构 | 只改公网监听字段，保留内部关系与全部用户 |
| Xray XHTTP + Reality 独立入口 | 无 CDN、拆分下载和额外映射时允许；不凭空生成上游未提供的 sing-box XHTTP 节点 |
| sing-box Reality、Hysteria2、Tuic | 已知独立结构可进入预检；最终须通过实际版本配置校验 |
| TLS/Nginx 共用、内部回落、跳跃/附加映射依赖、未知配置 | 只读或拒绝自动变更，显示原因 |
| Docker/OpenRC、自定义核心启动参数、未知原生防火墙 | 不宣称写入支持 |
| UFW/firewalld | 前端精确管理放行；复用规则不在回退时删除；未知规则保留 |
| 附加入口 | 只操作可唯一识别的非默认转发；默认入口及可能被订阅引用的删除不自动执行 |
| nftables 额度/到期 | 项目专属 `inet v2ray_agent_ports` 表；命名配额汇合双向/双栈，方向计数分开 |
| tc 限速 | 单外部接口、明确本地地址、默认路由；仅空/noqueue 或本模块已拥有的队列结构 |

**限速尚有实质限制：** `mq`、`fq_codel`、自定义 QoS、多个外部接口等会被保守拒绝，不会覆盖原队列。当前 flower 端口分类不能覆盖非首个 IP 分片，IPv6 扩展头等也尚待真实流量验收。`applied=true` 仅表示对象安装核验通过；`throughput_verified=false` 不应解释为满足严格吞吐量验收。生产发布前必须完善分类并完成 T28，而非仅放宽拒绝条件。

公开订阅采用已初始化的本地文件和缓存远程节点生成候选，分别验证每位用户的适用格式及已有 provider 引用。不在端口事务中安装 Nginx、下载远程模板、重新生成 Salt 或清空发布目录。缺失或陈旧的目标订阅先拒绝，需通过原订阅管理完成初始化。服务端发布成功后，客户端仍须重新拉取订阅。

## 恢复与维护

`/etc/v2ray-agent/.write.lock` 由中英文安装器、cron、交互管理及后台任务共用。旧菜单等待输入时释放锁，返回后核对配置/账户/订阅摘要；发现其他修改会要求重新操作。直接编辑文件的外部程序无法被 flock 强制约束，事务另做摘要核验。

私密状态位于 `/etc/v2ray-agent/port-manager/`：

| 路径 | 内容 |
|---|---|
| `transactions/<id>/journal.json` | 阶段、文件摘要、规则操作意图、恢复结果 |
| `transactions/<id>/backup/` | 仅本次涉及文件的恢复副本，可能含凭据，禁止公开 |
| `policies.sqlite3` | 策略、方向用量、月份、版本、故障和批次记录，不复制代理密钥 |
| `rates.json` | tc 对象归属、原速率、映射、未完成事务 |

下一次管理入口会处理未完成事务。自动恢复失败时阻止继续写入，并保留备份位置和故障状态。人工回退基于当前账户执行一次反向改端口，不覆盖后来增删的账户，也不恢复旧流量账本。

正常关闭后台会先停止受控流量并结算；异常断电、未知计数器重置或规则代次丢失会保留可信用量并标记故障。故障纠正必须有依据和记录，不得通过删数据库、回滚快照或重建相同数字端口返还已用量。`PolicyManager.acknowledge_fault()` 提供不降低可信用量的维护接口，尚没有面向普通用户的完整故障校正菜单。

不要在运行中直接删除策略表、IFB、队列、账本或服务依赖。首版尚无全量退役向导；旧卸载入口遇到策略状态会拒绝执行。退役应在维护窗口停止受控代理服务，保存私密账本/对象清单，由管理员核对并逐项撤销本模块对象和启动依赖，再恢复原网络配置。不得清空整机 nftables/iptables 或删除其他服务的队列。

更新来源已经改为 `ECHOAPi/v2ray-agent`；安装脚本记录模块的固定提交，模块完整下载和语法校验后才切换版本目录。脚本自身先下载并执行 `bash -n`，成功后替换；旧脚本保存在 `install.sh.previous`。草稿未合并前，master 的更新入口仍是原版本。
