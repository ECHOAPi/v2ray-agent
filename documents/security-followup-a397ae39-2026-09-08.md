## 候选准备和支持条件

支持的归档名称为 Linux amd64/arm64 的 Xray ZIP 与 sing-box tar.gz。版本标签须符合受限 v数字.数字.数字及可选预发布后缀格式。默认稳定版使用 latest，预览版从最近 20 条发布中选择首个非草稿预发布；Xray 回退列表从同一批发布中取最多 5 个稳定标签，不支持任意旧发布搜索。

每个选中资产必须唯一，并在 GitHub Release 元数据中提供有效的 sha256 摘要。下载强制 HTTPS 和 HTTPS 重定向，连接/总超时分别 15/120 秒，核心归档上限 256 MiB。摘要比对后只读取一个精确名称的普通二进制成员；重复成员、链接、空文件或超限文件拒绝，不解包其余成员。归档附带的配置和其他 Geo 不会覆盖本地文件。

已核对上游 [Xray v26.3.27 发布元数据](https://api.github.com/repos/XTLS/Xray-core/releases/tags/v26.3.27) 和 [sing-box v1.14.0 发布元数据](https://api.github.com/repos/SagerNet/sing-box/releases/tags/v1.14.0) 的目标架构资产及摘要字段；这是同源一致性校验，不是独立签名。旧发布缺少摘要会失败，不降级到无校验下载；GitHub 限流或网络错误也保留旧文件并返回失败。

候选二进制 version 输出必须匹配所选标签。Xray 还用新二进制校验候选 Geo，并在存在 JSON 配置时检查实际 conf 目录；没有配置的首次安装只检查二进制和 Geo，不声称协议已可用。sing-box 在私有副本上合并和执行 check，工作数据目录也是私有目录；参考 [sing-box check 实现](https://github.com/SagerNet/sing-box/blob/v1.14.0/cmd/sing-box/cmd_check.go)。没有源碎片时检查现存合并配置，两者都没有时只准备新二进制，协议配置由后续安装步骤生成。

原配置碎片的 JSON 必须是单一对象。DNS servers 类型非法或同一旧出站同时包含 domain_strategy/domain_resolver 时拒绝，不删除用户原数据来掩盖错误。已有 HTTP client/default 设置保留。兼容性转换并不保证所有旧版本都接受；回退目标检查失败就保留现有核心。自定义相对路径的证书、规则或其他资源可能不能在私有工作目录通过检查，需要人工迁移，不能强行跳过检查。

自动核心更新要求标准根目录、非符号链接的文件、root 拥有且组/其他用户不可写的核心目录，以及标准 systemd 服务。预检读取有效 User、DynamicUser、FragmentPath、ExecStart，要求静态 root 身份和脚本标准二进制/配置参数；非标准来源、启动命令、非 root/动态用户、OpenRC 或无法确定的 failed/activating 等状态都拒绝。属性输出格式依据 [systemd 255 的 show 实现](https://github.com/systemd/systemd/blob/v255/src/systemctl/systemctl-show.c)，未知格式失败而非猜测。不存在服务且不存在旧二进制视为首次文件安装；旧二进制存在但无标准服务时拒绝自动升级。

准备前后复核配置/订阅、已安装脚本、模块指针，以及目标二进制、标准服务文件/drop-in、标准 TLS 文件和 Xray Geo 摘要；服务状态也必须未变。协作写入期间发生修改则放弃候选，不覆盖另一操作。外部写入者若绕过共用锁仍不能保证原子协调，文件权限/ACL 的全面审计仍属于 A10。

## 核心备份与恢复

候选目录位于 /etc/v2ray-agent/xray/.core-update.* 或 /etc/v2ray-agent/sing-box/.core-update.*，顶层权限 0700。正式发布前记录：

- files：本轮发布的固定相对文件名，Xray 为二进制和两个 Geo；sing-box 为二进制和适用的合并配置。
- previous/：发布前存在的正式文件，保留原权限；不保存源碎片，因为合并器不修改它们。
- absent/：同名标记表示该文件在发布前不存在，补偿应恢复缺失状态。
- KEEP_RECOVERY：已准备进入正式发布，尚未确认完成或补偿完成。
- version / COMPLETE：目标版本及成功完成标记。

提交期间持共用写锁，以同文件系统 rename 逐个替换文件。仅原先 active 的目标服务执行重启；原先 inactive 的服务不启动，也不重启另一核心。重启等待 5 秒、活动检查 2 秒，各另有 1 秒强制结束宽限。服务预检每次调用也有 2 秒上限和 1 秒宽限。命令超时不等于 systemd 已取消排队作业；失败时恢复文件后只提交有超时的非阻塞重启请求，必须再次核对运行态，不输出“服务已恢复”。

普通错误与 INT/TERM/HUP 尝试恢复整个文件清单。恢复失败或发布中 SIGKILL 会保留 KEEP_RECOVERY 和备份；新的旧菜单写入入口、核心更新、Geo 更新和配置合并均拒绝继续，防止覆盖恢复资料。Python 策略后台仍可继续核对，未用删除账本或延长租约绕过限制。

遇到恢复提示，先停止重复更新，协调共用写锁，检查该目录的 files、previous、absent 和正式文件，决定恢复哪一组完整文件。恢复 old 组时需同时恢复对应二进制及 Geo/合并配置，并尊重原来“文件不存在”的状态；保留完整证据，再校验核心和服务/监听/策略状态。只有确认一致后才处理标记，不能仅删 KEEP_RECOVERY 继续安装。此版不提供一键强制解除或自动断电恢复；没有 fsync、多文件原子性或真实断电验收保证。

成功后目录改名为 .core-backup.* 并输出精确路径；旧文件备份不会自动淘汰。备份可能含凭证，应继续保持私有并监控空间；人工清理前先确认不涉及未完成恢复。若仅备份目录改名失败，会保留原私有目录并提示，不删除已存备份。准备阶段被强制杀死也可能遗留未发布的私有临时目录，不能据目录名称推断正式文件已被替换。
